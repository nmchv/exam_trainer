# Exam Trainer

Статический модульный тренажёр для подготовки к экзаменам. Первый зарегистрированный экзамен — ОГЭ по географии. Сейчас в проекте есть работающий программный каркас и искусственный демонстрационный банк; реальных заданий и материалов ОГЭ здесь намеренно нет.

Интерфейс использует визуальные токены nmchv.ru: шрифт Manrope, палитру `#08090b / #111318 / #191d24` и синий акцент `#5b8def`. Тёмная тема включена по умолчанию, переключатель сохраняет выбор в `localStorage`. Это самостоятельный интерфейс: изображения и иллюстрации nmchv.ru не копируются.

## Запуск

Требуется Node.js 20+ (без установки npm-зависимостей):

```sh
npm run dev
```

Откройте адрес из вывода команды (по умолчанию `http://127.0.0.1:4173`). Для проверки:

```sh
npm test
npm run check
npm run build
```

`npm run check` проверяет синтаксис JavaScript и все JSON-файлы. `npm run build` формирует `dist/` без bundler и серверных маршрутов; страница использует hash-маршруты (`#/training`), поэтому корректно работает на GitHub Pages.

## Возможности каркаса

- Реестр экзаменов и загрузка версионированных JSON-банков с проверкой схемы и уникальности ID.
- Раздельные движки генерации тренировки и полного варианта, проверки ответов, теории, баллов, прогресса и статистики.
- Типы ответов: `single_choice`, `multiple_choice`, `text`, `number`, `matching`, `ordering`, `short_answer`, `table`, `map`.
- Режимы случайного и последовательного подбора, выбора номеров, фильтров по тегам/сложности и заданий из списка ошибок.
- Таймер, навигация, автосохранение состояния, возобновление и точный повтор состава локальной попытки.
- Темы и адаптивная раскладка; компоненты интерфейса не содержат правила проверки заданий.
- Supabase Auth/данные/RLS и Edge Functions подготовлены для подключения проекта. Пока нет настроек Supabase, приложение прямо сообщает, что вход и синхронизация не настроены, и использует локальное хранилище для демонстрации.

Архитектурные решения описаны в [ARCHITECTURE.md](./ARCHITECTURE.md), база — в [DATABASE.md](./DATABASE.md), формат банка — в [JSON_FORMAT.md](./JSON_FORMAT.md).

## Supabase

1. Создайте проект Supabase и примените миграцию:

   ```sh
   supabase link --project-ref YOUR_PROJECT_REF
   supabase db push
   ```

   Либо выполните файл `supabase/migrations/20261107000000_initial.sql` через SQL Editor. `supabase/schema.sql` — psql-обёртка для той же миграции.
2. Укажите URL проекта и публичный `anon`/publishable key в `public/config.js`. Это клиентские значения. **Не помещайте в frontend, репозиторий или Pages `service_role` key.**
3. В Supabase Auth добавьте опубликованный Pages URL и локальный URL в список разрешённых Redirect URLs.
4. Задайте серверные секреты для Edge Functions в настройках проекта (Supabase устанавливает `SUPABASE_URL`, `SUPABASE_ANON_KEY` и `SUPABASE_SERVICE_ROLE_KEY` автоматически) и опубликуйте функции:

   ```sh
   supabase functions deploy check-answer
   supabase functions deploy finish-attempt
   supabase functions deploy get-statistics
   ```

5. Реальные ответы добавляйте только в `task_answer_keys`, а шкалы оценивания — в `exam_scoring_rules`, через доверенный административный процесс. Таблицы закрыты для `anon` и `authenticated`; Edge Functions используют серверный ключ только на сервере Supabase. Edge Functions не проверены против реального проекта в рамках этой версии.

До появления настоящего банка публичный fixture `public/database/oge/geography/tasks/demo.json` содержит ответы и помечен `demoOnly`. Это искусственные данные для тестирования и **не шаблон публикации реальных ответов**. Загрузчик отклоняет ответы в любом JSON-банке без флага `demoOnly: true`.

## GitHub Pages

GitHub Pages публикует содержимое корня ветки `main` (включая `CNAME` для `exam.nmchv.ru`). В **Settings → Pages → Build and deployment** выберите **Deploy from a branch → main → /(root)**. Отдельный workflow `.github/workflows/pages.yml` запускает тесты и проверяет production-сборку; он не запускает вторую публикацию, чтобы избежать конфликтов с Pages deployment. Приложение использует относительные пути и работает как на корневом домене, так и по адресу `user.github.io/repository`.

В `public/config.js` разрешено хранить только URL и публичный Supabase anon/publishable key. RLS и проверка прав должны оставаться включёнными.

## Добавление экзамена

1. Создайте каталог данных, например `public/database/ege/history/`.
2. Добавьте `exam.json` с перечнем файлов банков, режимами генерации и шкалой оценивания.
3. Разместите банки заданий в `tasks/*.json`, проверьте их по [формату JSON](./JSON_FORMAT.md) и схемам из `schemas/`.
4. Для публичного банка оставляйте правильные ответы вне JSON: поместите их на серверную сторону в Supabase.
5. Добавьте запись с уникальным `id` в `public/database/registry.json`. Программный движок изменять не требуется.

Создавайте только явно вымышленные fixtures для тестов. Перед публикацией реального контента заполните приватные таблицы ответов и оценивания, включите Auth/RLS и проверьте функции в своём Supabase-проекте.
