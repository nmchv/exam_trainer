# Supabase: таблицы и безопасность

Миграция `supabase/migrations/20261107000000_initial.sql` создаёт схему, индексы, RLS-политики, привилегии и триггер профиля. `supabase/schema.sql` запускает эту миграцию через `psql`; для Supabase CLI используйте `supabase db push`.

| Таблица | Назначение | Доступ |
|---|---|---|
| `profiles` | Профиль, имя и username | Пользователь читает и меняет только собственную запись; профиль создаёт триггер `auth.users`. |
| `attempts` | Режим, экзамен, статус, время и серверный итог | Пользователь читает/создаёт/обновляет незавершённые попытки только с собственным `user_id`. Колонки баллов и `finished_at` ему недоступны на запись. |
| `attempt_tasks` | Состав, позиция, вариант и баллы позиций попытки | Чтение и редактирование только для попыток владельца. Поле `awarded_score` доступно Edge Function, не клиенту. |
| `attempt_answers` | Ответ пользователя и результат его проверки | Клиент может записать свой ответ; `is_correct` и `awarded_score` заполняет Edge Function. |
| `task_progress` | Счётчики правильных/всех решений | Пользователь читает только собственные строки; изменяет только Edge Function. |
| `user_settings` | Настройки профиля | CRUD только собственной записи. |
| `task_answer_keys` | Приватные ключи, правила проверки и объяснения | Таблица закрыта для `anon`/`authenticated`; доступна серверной роли Edge Functions. Не открывать таблицу клиентскому API. |
| `exam_scoring_rules` | Шкала перевода первичного балла в оценку | Только серверная роль Edge Functions. |

Все пользовательские таблицы включают RLS; связанные строки проверяют владельца через `attempts.user_id`. Сервисная роль используется только внутри Supabase Edge Functions и не передаётся браузеру. Публичный `anon` key сам по себе не является секретом, но не заменяет RLS.

## Сохранение и оценивание

Клиент создаёт попытку в статусе `in_progress`, сохраняет позиции и ответы. `check-answer` требует действующую пользовательскую сессию и проверяет, что задание входит в незавершённую попытку владельца. `finish-attempt` повторно проверяет владельца, читает приватные ключи, рассчитывает баллы, завершает попытку и обновляет `task_progress`. Клиент не может отправить серверные баллы или признак правильности благодаря колонковым привилегиям.

Создайте строки `task_answer_keys` и `exam_scoring_rules` доверенным административным способом после проверки банка. Не добавляйте ответы в открытые JSON. В рамках локальной версии реальный проект Supabase и production-ключи не предоставлены, поэтому миграции и функции подготовлены, но подключение/работа RLS не выдаются за проверенные.

## Auth настройки

В Supabase Auth добавьте локальный URL и GitHub Pages URL в Site URL / Redirect URLs. Политики email-confirmation задаются в Supabase. При недоступной конфигурации интерфейс не создаёт фиктивную сессию и показывает, что вход не подключён.
